### Targeted Refresh Performance Fix

Measurement identified an unrelated blocking request: `App.tsx` waited for `Promise.all([loadSession, listSessions])` before parsing and selecting the requested event. Listing discovers and loads other recent logs, even when the user only wants one cited event. In the first instrumented refresh, the target API completed in 869 ms while the list took 8,854 ms. This was not a 35 MB browser-download bottleneck: the normalized evidence response was 2,290,474 bytes.

The only product-code change removes the list from the deep-link load path and loads it when the session picker is opened. Picker loading/errors are separate from session loading; closed-picker responses are ignored. Discovery, parsing, payloads, and backend caching were not changed. Listing can still take time when explicitly requested; this is not a general large-log optimization.

Same inactive 35,256,266-byte source, same event, same running local MCP server, production web assets, and an isolated Edge Playwright session. Timings measure `page.reload()` to the selected row becoming visible; API durations come from browser resource timing. Three consecutive reloads were taken before editing, then three after rebuilding. All six selected the same event and returned the same evidence-response size.

| Sample | Refresh to selection (ms) | Target API (ms) | Session-list API (ms) |
| --- | ---: | ---: | ---: |
| Before 1 | 9,592 | 869 | 8,854 |
| Before 2 | 1,956 | 152 | 1,572 |
| Before 3 | 1,917 | 148 | 1,387 |
| After 1 | 2,215 | 960 | Not requested |
| After 2 | 1,491 | 813 | Not requested |
| After 3 | 1,562 | 884 | Not requested |

The earlier 15,086 ms observation remains historical; it was not reproduced exactly in this measurement. The median of these three observations changed from 1,956 to 1,562 ms. Cache state and machine load were not reset or controlled, and discovery includes changing logs, so these are local observations, not cold-start results, percentiles, or a guaranteed speedup. The causal finding is the removed dependency on listing other sessions. Local measurement scripts and private browser screenshots remain under `output/maintenance-e2e/`.
